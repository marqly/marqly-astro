# ADR-006: `/bookmark-manager` pillar for the head term

- **Status:** accepted
- **Date:** 2026-10-05
- **Phase:** 3.1/3.2 (considered)

## Context
Owner snapshot §2.5: "bookmark manager" pos **39.1** (8K imp/3mo), "online bookmark manager" 52.9,
"bookmark manager for chrome" 22.2. No dedicated `/bookmark-manager` page exists — the head term is
answered by the homepage (pos 6.8, brand) and scattered `/for-*` landers. A canonical pillar that
defines "what a bookmark manager is / how to choose / vs browser bookmarks" and links every cluster
is the highest-leverage money-page addition.

## Decision
Create `/bookmark-manager` (EN, indexable, answer-first + decision table + FAQ + links into every
cluster). Info-gain element: a real selection-criteria decision table + a "vs the browser's own
bookmarks" comparison + PAA answers — none of the current pos-39 competitors is Marqly, so this is a
genuine addition, not a duplicate. It is the owner for the generic head term; `/bookmark-organizer`
and `/bookmark-manager-for-chrome` stay distinct intents (no cannibalisation).

## Consequence
One new money page + `changes-log.csv` entry. Must pass the info-gain gate (named in `seo/briefs/`).
