Rarely do two tools share values this completely and outputs this little. Both are open source. Both cost nothing to own. Both exist so your saved content answers to you rather than a platform. But Wallabag stores articles in a server database and serves them to a queue — web app, phone apps, offline reading, RSS feeds of your saves — while Obsidian Web Clipper writes each capture as a plain Markdown file into a local vault, where it becomes raw material for a knowledge base rather than an item to be read and archived.

**Choose Wallabag if:**

- You want sync without thinking: your server (or €11/year wallabag.it) feeds every device, no add-ons required.
- A reading workflow matters — queue, offline mobile apps, annotations, public share links for individual articles.
- You'd rather browse a library than tend a vault.

**Choose Obsidian Web Clipper if:**

- Clips should live forever as portable plain-text files on your disk, immune to any service's fate.
- You capture with intent: highlighter mode grabs the passages you mark, and per-site templates auto-title, tag, and file each clip from page metadata.
- You want optional AI at capture — the Interpreter summarizes, extracts, or translates using your own API key or a free local Ollama model.

The trade-offs mirror each other. Obsidian's clipper has no cloud: cross-device sync means Obsidian Sync at $4/month or DIY workarounds, there's no web app, and organizing or finding clips is manual — no automatic tagging, no semantic search. Wallabag asks you to run (or rent) a server and accept a dated interface with zero AI. Neither choice is wrong; they're different verbs. If your saves are things to read and finish, take Wallabag. If they're things to keep and build on, the vault wins.
