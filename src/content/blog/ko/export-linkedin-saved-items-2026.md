링크드인에 저장물용 공식 내보내기는 하나뿐입니다: 설정 및 개인정보 보호 → 데이터 개인정보 보호 → 데이터 다운로드, 그 안에 전용 **Saved Items(저장 항목)** 카테고리가 있습니다. 이름 그대로의 결과물 — 북마크를 눌렀던 모든 기사·게시물에 대해 받는 것은 **저장 날짜와 URL**이고, 내용 자체는 절대 안 들어 있습니다. 검증된 경로, 아카이브에 들고 안 드는 것(뉴스레터: 거의 안 듭니다), 그리고 2열 표를 리서치 라이브러리로 바꾸는 방법을 아래에 담았습니다.

## 링크드인에서 '저장'이 실제로 뜻하는 것

링크드인의 Save 버튼은, 조용히 '요청할 가치 있는 내보내기' 1순위가 되었습니다. Saved Items 카테고리에 타임스탬프가 붙어서요. 다만 범위에 함정이 있습니다.

- **사본이 아니라 링크.** 저장한 게시물은 다른 멤버의 데이터입니다. 링크드인은 '내 개인 데이터만 제공하고 다른 멤버의 데이터는 아니다'라고 분명히 말합니다(2026년 10월 5일 기준, https://www.linkedin.com/help/linkedin/answer/a1339364 ). 삭제된 게시물은 Saves 화면에서 썩는 그대로 아카이브 안에서도 썩습니다.
- **채용은 별도.** 저장한 채용공고, 저장한 채용 알림, 지원은 각각 자기 카테고리를 가집니다. Saved Items은 기사·게시물 저장이지 '저장' 개념 전체가 아닙니다.
- **구멍은 뉴스레터.** 뉴스레터 팔로우는 내보내기 카테고리에 없고, '읽음으로 저장한' 발행물도 항목별로 나오지 않습니다. 아래에 계속.

Saves가 앱 안 표시 능력을 넘어섰다면 — [X 북마크](/ko/blog/export-twitter-x-bookmarks-2026)와 같은 고장 방식 — 밖으로 꺼내는 방법이 이겁니다.

## 단계별: Saved Items 내보내기 요청

링크드인 도움말 기사 '데이터 다운로드'가 현행 경로를 보여 줍니다(2026년 10월 5일 기준, https://www.linkedin.com/help/linkedin/answer/a1339364 ).

1. linkedin.com에서 홈페이지 상단의 **Me 아이콘** 클릭.
2. **설정 및 개인정보 보호** 선택 (https://www.linkedin.com/psettings/data-privacy/ 로 직접도 가능).
3. 왼쪽 레일에서 **데이터 개인정보 보호** 클릭.
4. **링크드인이 내 데이터를 사용하는 방식** 섹션에서 **데이터 다운로드** 클릭.
5. **찾는 데이터 선택**을 고르고 **Saved Items(저장 항목)**에 체크 — 같은 요청에 **저장한 채용공고**, **기업 팔로우**, **연결**도 원하면 추가.
6. **아카이브 요청**을 누르고, 메일이 오면 **72시간 안**에 다운로드.

기사가 못 박는 세 가지 규칙을, 사람들이 깜짝 놀라는 김에 다시 적습니다. 다운로드는 **개인 컴퓨터**에서 실행해야 하고 모바일에서는 지원되지 않습니다. 카테고리 지정 요청은 **몇 분 안**에 메일이 오고, 전체 다운로드는 접수 메일까지 **24시간** 걸릴 수 있습니다. 그리고 카테고리는 시계가 달라서, Saved Items은 **48시간** 배치 쪽입니다. 내 계정에 있는 카테고리만 받습니다 — 자격증을 등록한 적 없으면 자격증 파일은 오지 않고, Saves가 비어 있으면 저장 항목 파일도 오지 않습니다.

## 파일에 실제로 들어 있는 것

링크드인의 카테고리 자체 설명대로:

- **Saved Items** — '게시물, 기사, 기타 콘텐츠의 저장 날짜와 URL'.
- **저장한 채용공고** — 저장 날짜, 공고 제목, 회사명, 링크드인 게시 URL.
- **저장한 채용 알림** — 검색 문구와 날짜.
- **기사(Articles)** — *내가* 발행한 기사의 URL(저장한 기사가 아님).
- **기업 팔로우 / 멤버 팔로우** — 이름과 팔로우·해제 날짜.
- **리액션, 댓글, 공유** — 체크하면 내 참여의 날짜와 URL.

그래서 Saves 내보내기는 2열의 진실입니다: **언제 저장했고, 어딘지를 가리켰는지**. 실무 귀결 두 개.

1. **링크드인 게시물 URL은 로그인 장벽 안.** `linkedin.com/posts/...` 는 로그인하지 않은 사람에게는 열리지 않고, 외부 수집기는 스텁만 얻습니다 — 내 아카이브조차, 10년 뒤에 다시 못 열 링크를 안고 있게 됩니다. 외부 기사 저장(출판사로 리다이렉트되는 것)이 오래 남는 쪽입니다.
2. **채용 링크는 생것.** 링크드인 게시 URL은 공고가 닫히면 사라집니다. Saved Items의 채용 쪽은, 레퍼런스 체크 때가 아니라 아직 필요한 그날에기록으로 옮겨 두세요.

그리고 정직한 구멍: **뉴스레터**. 뉴스레터를 팔로우하고 그 게시물을 저장할 수는 있지만, 링크드인의 공개 내보내기 카테고리 목록에 뉴스레터 칸은 없습니다. 기업·멤버 팔로우는 '누구를 팔로우했는지'까지고, 발행물 자체는 내보내기 가능한 데이터셋이 아닙니다. 목록 밖이 필요하면 링크드인은 데이터 접근 요청 양식으로 안내합니다(2026년 10월 5일 기준, https://www.linkedin.com/help/linkedin/ask/TS-DCR ) — 느리고, 구조 보장 없음. EU/EEA/스위스 멤버는 여기에 더해 https://www.linkedin.com/help/linkedin/answer/a6214075 에 문서화된 프로그램 경로도 쓸 수 있습니다.

## 표를 라이브러리로

내보내기는 '날짜 달린 URL 목록' — 지식베이스가 아니라 원료입니다.

**최속의 좋은 결과: 취사와 재저장.** 저장 항목 목록의 절반(최신쪽)을 처리하세요. 실체가 외부 기사 — 업계 칼럼, 채용 벤치마크, 에세이 — 인 것은 열어, [평소 쓰는 브라우저의 북마크 관리자](/ko/bookmark-manager-for-chrome)로 제대로 저장(Chrome, Edge, Firefox, Safari에 iOS·Android 앱까지). 제목도, 페이지 전체도, 내 태그도, 나중에 실제로 검색할 장소에 남습니다.

**일괄 경로: 변환 후 가져오기.** 저장 항목 파일을 스크립트나 AI 어시스턴트에게 넘겨 URL 열만 있는 단순 CSV를 쓰게 하세요(날짜 열은 내 기록용으로 남겨 두고 — 이유는 아래). Marqly는 범용 CSV, 브라우저 북마크 HTML, Raindrop HTML, Pocket의 list.csv를 `.html` / `.htm` / `.csv`로 받습니다 — 무료 플랜 10MB까지, Pro(연 72달러) 30MB까지, 파일당 북마크 10,000개. 가져올 때 링크는 수집되어 색인되므로, 외부 기사 저장은 제목 달린 읽을 수 있는 항목으로 되살아납니다 — 반면 `linkedin.com/posts` 링크는 위의 로그인 장벽 때문에 얇게 들어옵니다. 한도는 돌려 말하지 않습니다: **링크드인 저장 날짜는 가져오기를 통과하지 못하고** — 모든 항목이 가져온 날짜를 갖고 — **가져온 항목의 자동 태깅은 Pro 기능**입니다. 무료 플랜은 파일에 직접 넣은 태그를 그대로 보존합니다. 본 운영 전에 변환 파일을 [북마크 파일 뷰어](/tools/bookmark-file-viewer)로 확인하세요.

**아카이브보다 재구축이 이기는 법:** 직업용 저장을 구해 오는 목적은, 식은 상태에서도 다시 찾는 것입니다. '3분기 그 공급망 글'은, 언제 저장했는지 기억이 아니라 설명만으로 나와야 하고 — 그게 [AI로 북마크 검색](/ko/blog/ai-bookmark-geomsaek-2026)의 역할입니다. 수백 줄짜리 저장 항목 목록을 안고 있는 리서처라면 더욱([연구자용 페이지](/ko/for-researchers) 참고). 저장의 '읽기 큐'쪽 반은, [Pocket 대안 경로](/ko/alternatives/pocket)가 같은 변환 문제를 반대편에서 다룹니다.

## Marqly를 쓰면 안 되는 때

- **컴플라이언스 사본.** 내보내기가 기록 요구나 GDPR 포터빌리티용이라면(링크드인 개인정보 처리방침이 권리를 안내: https://www.linkedin.com/legal/privacy-policy ), 손대지 않은 링크드인 아카이브를 그대로 보관 — 큐레이션된 라이브러리는 같은 산출물이 아닙니다.
- **네트워킹 데이터.** 연결, 메시지, 초대장은 '사람' 모양의 데이터로 자기 도구와 윤리가 따로 있습니다. 북마크 관리자가 집으로 알맞은 종류가 아니에요.
- **진행 중인 취업 파이프라인.** 저장한 공고를 지금 운용 중이라면, 링크드인 자체 Jobs 경험이 어떤 재저장보다 낫습니다. 내보내기는 지난 탐색을 정리하는 쪽에 쓰고, 진행 중 탐색에 쓰지 마세요.

## 자주 묻는 질문

**링크드인 저장 항목은 어떻게 내보내나요?**
Me 아이콘 → 설정 및 개인정보 보호 → 데이터 개인정보 보호 → 데이터 다운로드 → Saved Items 체크 → 아카이브 요청. 카테고리 지정은 몇 분 내 메일, 다운로드 링크는 72시간. PC 전용(2026년 10월 5일 기준, https://www.linkedin.com/help/linkedin/answer/a1339364 ).

**내보내기에 저장한 내용이 들어가나요?**
아니요 — '게시물, 기사, 기타 콘텐츠의 저장 날짜와 URL'만. 링크드인은 다른 멤버의 데이터를 명시적으로 내보내지 않으니, 저장한 게시물은 링크로 옵니다.

**팔로우한 뉴스레터를 내보낼 수 있나요?**
공개 목록에 뉴스레터 카테고리가 없습니다. 팔로우 대상(기업·멤버)은 내보내되, 발행물은 안 됩니다. 목록 밖은 데이터 접근 요청 양식의 영역이고, 출력은 느르고 불명확합니다.

**아카이브가 조각조각 온 이유는?**
카테고리는 두 시계로 발송됩니다 — 10분 배치와 48시간 배치 — 그리고 전체 계정은 접수 메일만 24시간 안. Saved Items은 느린 배치입니다.

**저장 항목 파일을 Marqly로 가져올 수 있나요?**
먼저 URL 열이 있는 CSV로 변환 — Marqly는 범용 CSV, 북마크 HTML, Pocket, Raindrop HTML을 받습니다. 저장 날짜는 보존되지 않고(항목은 가져온 날짜를 갖고), 자동 태깅은 Pro입니다. 절차의 세부엔 차이가 없습니다([Chrome 북마크 가져오기 안내](/ko/blog/chrome-bookmark-gajyeoogi-2026)).

## 한눈에 정리

1. **설정 및 개인정보 보호 → 데이터 개인정보 보호 → 데이터 다운로드**, **Saved Items** 체크, 개인 컴퓨터에서 요청.
2. 산출물은 **날짜＋URL 표**를 기대 — 좁은 요청은 몇 분 내 메일, 다운로드는 **72시간** 안에.
3. **내용 없음, 뉴스레터 내보내기 없음.** 링크드인 내 링크는 로그인 장벽 뒤에서 썩으니, 취사는 일찍.
4. 남길 것은 CSV로 변환해 검색되는 크로스플랫폼 라이브러리 — [Marqly](https://app.marqly.com) 같은 — 에 가져오기. 단 가져오기는 오늘 날짜를 찍고 내 저장 날짜는 옮기지 않는다는 것을 알면서.
