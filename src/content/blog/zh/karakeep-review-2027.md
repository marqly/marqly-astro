## 与 2026 年版相比改了什么

六处更正，外加三件旧版根本没有覆盖的事。

1. **我们自家对比表里的云端 Pro 价格是错的。** 2026 版那张 Marqly 对 Karakeep 的表把 Karakeep 的云端总价写成「每月 6 美元」，实际是**每月 4 美元**。表格上方的正文写对了，表格没写对——于是在读者唯一会扫的那一行里，我们把 Karakeep 少报了一半。
2. **我们引用过的云端方案限制并不在事实表里。** 2026 版列过「5 万条书签、50 GB」的 Pro 额度、「20 MB」的免费额度、一个带 SSO 的企业档，以及七天退款保证。我们能核实的只有两条：**0 美元档上限 10 条书签**，**Pro 每月 4 美元且没有公布年付价格**。其余的我们直接删掉了，而不是继续复述无法溯源的数字。如果哪天 Karakeep 公布了云端年付价，那才是该信的数字。
3. **我们引用的版本落后了两代。** 旧版写的是「v0.31.0 于 2026 年 2 月发布」。目前的记录是 **0.33 版，2026 年 8 月发布，带来了语义检索**——这个标记更有用，因为它给功能定了日期，而不只是给构建号定了日期。

5. **导入清单不完整。** 旧版只点了 Chrome、Pocket、Linkwarden 和 Omnivore。Karakeep 的导入器覆盖 **Pocket、浏览器书签 HTML、Omnivore、Instapaper、Linkwarden 和 mymind**——对正在抢救一个已死或被弃书库的人来说，多了两个落脚点。
6. **无法溯源的说法一律撤掉。** 「图片 OCR」、RSS 摄取、基于规则的自动化引擎、Floccus 双向同步、20 MB 免费额度、「190+ 贡献者」，这些在 2026 版里都出现过，但都不在我们核实过的事实表里。事实表真正记录的是 **REST API、webhooks、CLI 和一个 MCP 服务器**——用于把 Karakeep 接进 AI agent——外加**公开清单上的 RSS 订阅源**。这是一个比我们当年讲的更强的自动化故事，也是我们能守住的那一个。

## Karakeep 是什么

Karakeep 是一个开源的「收藏一切」应用，由你自己部署，通常用 Docker。它把链接、笔记、图片、视频和 PDF 存在你自己的服务器上，并且会为每条链接存档完整页面，让书库扛得住链接失效。它最初叫 **Hoarder**，2025 年初因为一场商标纠纷更名 Karakeep——同一套代码、同一批维护者、一个新名字。如果你是从老的 Hoarder 安装过来的，什么都没有换掉：项目一直在继续。

有两条主张定义了它，而且两条都是承重墙。

第一条是**所有权**。你的书签、你的页面存档、你的数据库、你的备份。没有会丢的账号，没有要吞下的条款变更，也没有哪家公司一消失就把你的书库带走。在这个品类八个月内发生两次关停之后，这已经不再是一种立场，而是一份风险评估。

第二条是**你自己提供的 AI**。Karakeep 不卖给你一个智能层，它把一个接进来。指向任意 OpenAI 兼容 API，它就自动打标签和写摘要；指向同一台机器上跑的 **Ollama**，它做同样的事，而你的书签从不离开内网。没有任何托管竞品能在任何价位上提供第二个选项，而对一部分读者来说，仅这一条事实就决定了买不买。

它仍然是 1.0 之前的软件，版本号对此很诚实；发布节奏稳定，文档成型，社区完整穿过了那次更名。

## 核心功能

- **AI 自动打标签与摘要，云端或彻底本地。** 每一次保存都可以由你选的模型来打标签和写摘要。真正独特的是它*跑在哪里*：接托管 API 换质量，或者接本地 Ollama 模型换隐私。质量取决于你的硬件跑得动什么——小模型给出的标签明显比前沿 API 粗糙——但「这个选项存在」本身就是重点。
- **全文、语义与混合检索。** 搜索由 Meilisearch 支撑，覆盖你收藏内容的完整正文，2026 年加入了语义与混合模式。检索质量依然取决于你的配置和嵌入模型，但这个架构明显领先于多数停在关键词匹配的自建同类。
- **整页存档。** 每条链接都会保存为一份页面副本、一张截图和一个 PDF，视频可以用 yt-dlp 拉下来。这是让 Karakeep 书库成为档案而不是一串 URL 的那个功能，也是最快把你磁盘填满的那个功能。
- **高亮与批注笔记。** 两者都有，2026 版漏掉了。你可以对存下来的东西做标记，而不只是把它归档。
- **可公开分享的清单，带 RSS 订阅源。** 一个清单可以被发布并被订阅，这在自建工具里很少见，对为读者而不是为自己做策展的人很有用。
- **带离线阅读的移动应用。** 原生 iOS 与 Android 应用，2026 年新增离线阅读，外加系统分享菜单保存。
- **Chrome、Firefox 与 Safari 扩展。** 对一个开源项目来说，客户端覆盖面堪称豪华，在 Safari 这一项上还赢过几款商业产品，包括我们自己的。**它不包含 Edge。**
- **REST API、webhooks、CLI 和一个 MCP 服务器。** 这是它的自动化面，而 MCP 服务器是 2027 年真正要紧的那部分：它让一个 AI agent 直接读取并操作你的书库。在我们的数据层里，Karakeep 是唯一自带 MCP 服务器的自建管理器。
- **读起来像品类讣告的导入清单。** Pocket、浏览器书签 HTML、Omnivore、Instapaper、Linkwarden、mymind。这六个服务里已经有两个不在了，它们的书库最后都去了 Karakeep。

真正缺什么同样要紧。**没有对自己收藏的 AI 问答**——你没法提一个问题、拿回带出处的答案。**没有针对 YouTube 的 AI 功能**：yt-dlp 能存档视频，但播放页上没有摘要层、没有字幕层、也没有对话层。扩展里也**没有一键保存全部打开的标签页**。

这张表可以读出三件事。

**免费档是样品，不是方案。** 10 条书签能告诉你界面加载得起来、你喜不喜欢它的形态。它告诉不了你任何关于「和 Karakeep 一起生活」的事——不能说明打标签的质量，不能说明有量之后的检索，也不能说明存档一个跟解析器较劲的页面会怎么样。任何正在「自建」和「每月 4 美元」之间做选择的人都应该明白：云端免费档无法为这个选择提供信息。

**每月 4 美元的云端价格是这个品类里最便宜的托管 AI**——但它是公测产品上的公测定价，这是一个真实的警告，不是一句客套。公测服务会改档位。在你把十年的收藏交进去之前，请先读下面的耐久性一节。

## 三年和五年，Karakeep 到底要花多少钱

订阅是一个小数字重复很多次，自建是一个零重复很多次再加上你的夜晚。下面是只用核实过的价格做的算术，假定你不换方案、价格也不动：

自建那一行是所有人都在引用的，也是最误导人的一行。**软件授权确实永久 0 美元**——这部分不是营销话术。但一套自建 Karakeep 的诚实总成本还有另外四项，没有一项是零：

- **基础设施。** 一台永远开着的机器，磁盘要装得下整页存档、截图、PDF 以及所有 yt-dlp 拉下来的视频。如果你本来就在跑 homelab，这是你无论如何都要付的那张账单上的一个零头；如果你没有，那它就是「每年 48 美元的云端订阅看起来很便宜」的原因。
- **AI 用量。** 自带 Key 就是自带计量表。用一个前沿 API 给成千上万条收藏打标签和写摘要，按每千 token 算是真金白银；本地模型每次调用不花钱，但需要跑得动它的硬件。这里我们不编数字，因为它完全取决于你的书库规模和模型选择——但「免费的 AI」只在 Ollama 这条路上成立。
- **时间。** 如果 Docker 在你的舒适区里，安装是一个晚上的事；不在，它是一堵墙。之后还有更新、你真的会去测一遍的备份、反向代理的安全，以及 0.x 版本偶尔要你执行的迁移步骤。
- **风险。** 1.0 之前的软件跑在你自己的硬件上，载荷是你的整个书库。备份是你的工作，发现备份早就坏了也是你的工作。

把这笔账老实算完，决定就不再是「免费对 4 美元」，而是「每月 4 美元加别人的传呼机，对 0 美元加你自己的」。两种都理性，只是通常只有一种会被如实摆出来。

## 耐久性与可携带性：什么能活得比项目久

这是 2026 版没写的一节，而在 2027 年，它才是该决定买不买的那一节。**Omnivore 在 2024 年 11 月关闭**，团队被 ElevenLabs 收编，导出截止日是 2024 年 11 月 30 日。**Mozilla 在 2025 年 7 月 8 日关停了 Pocket**；导出通道与 API 在 **2025 年 11 月 12 日**关闭，数据删除从那天开始排队执行，Premium 订阅者拿到了按比例退款（来源：`https://support.mozilla.org/en-US/kb/future-of-pocket`）。这个品类里两款最受喜爱的保存工具在八个月内相继消失，而其中一款的所有者是一家基金会，不是一家创业公司。

对照这份记录，Karakeep 的耐久性论据是我们覆盖的所有产品里最强的——而且理由和它背后那家公司毫无关系。

**授权与代码。** Karakeep 是开源的，开发在公开场合进行。如果维护者停手，代码不会消失：它可以被 fork 并继续运行，而这恰恰就是 Omnivore 代码库后来的遭遇。一个关停的托管服务会把产品一起带走；一个停摆的开源项目留给你的是一套还能用的安装。

**收入模式。** 自建应用免费，不依赖任何人的营收。Karakeep Cloud 是变现路径，仍在公测，它携带的风险是对*托管*的风险，而不是对你书库的风险——无论云业务活不活得下去，一套自建安装都继续工作。这和「免费但没有营收」的托管服务是真正不同的姿态，而后者正是杀死 Omnivore 的那个模式。

**导出通道。** Karakeep 可以在设置里导出整个书库，格式是它自己的 JSON，或者**标准 Netscape 书签 HTML**——几乎所有其他管理器都能导入的那个格式——导出内容包含你的清单，也支持自动备份。如果你是自建的，数据本来就躺在你自己拥有的数据库里，所以导出是一种便利，而不是一条逃生通道。

**导入通道。** Pocket、浏览器书签 HTML、Omnivore、Instapaper、Linkwarden、mymind。Karakeep 是一个净进口已死服务的地方，而这个品类里一款工具能发出的最让人安心的信号就是这个：维护者是在为带着一份档案来的人做产品，而不只是为从零开始的人。

**诚实的那句警告。** *软件*的耐久性不等于*你这套部署*的耐久性。一套自建 Karakeep 只有在你会持续打补丁的前提下才熬得过项目停摆，而一个暴露在公网、长期不更新的 Docker 容器，结局比一个关停的 SaaS 更糟。你是在用供应商风险换运维风险。这笔交易值得做——但它是一笔交易，不是一次逃脱。

如果你读到这里是因为手上有一份旧档案要抢救，而不是要新建一个书库：我们的 [Pocket 替代品盘点](/zh/blog/pocket-tidai-2026)走了一遍整个赛道，[导入保真度研究](/research/bookmark-import-fidelity)报告了一次真实迁移里到底有什么活了下来——测量时间是 2026 年 9 月 26 日：一份 Pocket 导出压缩包里的 HTML 预览文件，261 条只解析出 0 条；而一份 Chrome 书签导出，43 条解析出 43 条。你喂给导入器的格式，比导入器本身更要紧。

- **真正的数据所有权。** 链接、笔记、图片、页面存档，甚至 AI 处理过程本身，都可以完全活在你控制的硬件上。

## Karakeep 的短板

- **你就是系统管理员，而且是永久的。** 安装、更新、备份、存储膨胀、反向代理的安全，从此都是你的工作。整页存档填满磁盘的速度比多数人预想的快。
- **1.0 之前的软件。** 0.x 的版本号很诚实：升级偶尔要执行迁移步骤，稳定性不错，但没有商业级承诺。
- **AI 质量是你配置的功劳，也是它的锅。** 接付费的前沿 Key，结果很强；在一台配置平平的机器上跑小模型，标签和摘要就会变粗糙。灵活性是功能，方差是它的价格。
- **云端免费档证明不了这款产品。** 10 条书签低于「打标签质量、语义检索、存档」开始显形的那个量级。
- **云端是公测，而且没有公布年付价格。** 只有两个档位，公测产品上的公测定价。在没有导出习惯的情况下，别把十年的收藏放进去。
- **不能对自己的收藏提问。** 没有任何档位——自建或云端——能让你提一个问题、拿回带出处的答案。它的 AI 会归档，不会对话。
- **没有 YouTube AI。** 视频可以用 yt-dlp 存档，但播放页上没有摘要、字幕或对话层。
- **没有 Edge 扩展。** 只有 Chrome、Firefox、Safari。如果 Edge 是你的日常浏览器，你就只能从网页界面或者手机分享菜单保存。
- **没有一键保存全部标签页。** 扩展里的批量采集不存在。
- **与成熟商业应用之间的完成度差距。** UI 是真心不错，但并排放着你还是会看到接缝：阅读视图的毛边、偶尔解析失败的页面、进度落后于网页端的移动应用。

## 谁应该跳过 Karakeep

真实的判负理由，按人们撞上的顺序排：

- **你存很多 YouTube，并且想要摘要。** Karakeep 可以用 yt-dlp 存档视频，但不能给它写摘要、不能在播放页上出字幕、也不能和它对话。

- **你想要一个有公布年付价格、有支持邮箱的服务。** Karakeep Cloud 是公测状态，两个档位，没有公布的年付数字。
- **你要批量采集打开的标签页。** 扩展里没有一键保存全部标签页。

而**不该**跳过它的人是这些：homelab 玩家；想要 AI 但链路上不能有云的隐私优先用户；需要页面与视频存档的数据囤积者；真的会用 API 和 MCP 服务器的开发者；以及那些用得来 Docker、宁愿自己拥有这场抢救而不是租一场的前 Pocket 或前 Omnivore 用户。在这个画像里，Karakeep 是整个书签品类里性价比最高的一款，而且差距不小。

## 结论
