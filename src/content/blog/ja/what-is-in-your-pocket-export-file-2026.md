**Pocketのエクスポートファイルは、保存リンクの一覧＋メタデータ（URL、タイトル、タグ、各項目の追加日時、未読かアーカイブか）です。** 記事の複製ではありません。通常はCSV（たまにZIP圧縮で、ライブラリが大きいと複数ファイルに分割）で、実用上の結論は「元のページがまだ生きているうちにインポートする」——記事本文はファイルには入っていないからです。

Mozillaがシャッターを下ろす前にライブラリを書き出せたあなたは、いまファイルと向き合っているはずです——`pocket-export.csv`かもしれないし、ZIPかもしれない、番号付きCSVのフォルダかもしれない。中に何が入っていて、信頼して大丈夫なのか、このガイドで箱を開けます。すべての列を解読し、フォーマットとその癖を説明し、インポートで人を躓かせる落とし穴に旗を立て、そのファイルを「検索できるライブラリ」に戻す手順まで示します。「どこへ移るか」の全体像を先に知りたいだけなら[Pocket代替アプリ8選](/ja/blog/pocket-daitai-2026)が担当ページで、ここでは「ファイルそのもの」だけ扱います。

## Pocketのエクスポートファイルに含まれるもの

Pocketのエクスポートには、保存した項目1つにつき1行が並び、各行は同じいくつかのフィールドを持ちます：リンク、タイトル、あなたのタグ、追加した時のタイムスタンプ、読了ステータス。ペイロードはこの通り——「何を・いつ保存したか」の構造化リストであって、ページの中身ではありません。「図書館の精密な索引」であって、蔵書そのものではない、と考えると正確です。

各フィールドを噛み砕いて説明します：

- **URL** — 保存したWebアドレス。このファイルの背骨で、他はすべてそれにぶら下がるメタデータです。URLがまだ解決されれば保存は再構築できますが、404ならリンクは行き止まりです。
- **Title（タイトル）** — 保存時にPocketが取得したページタイトル。たいていは記事の見出しですが、Pocketがうまくパースできなかった場合は汎用的なサイト名になっていることもあります。
- **Tags（タグ）** — あなたが付けたタグ。1つのフィールドに区切り文字（縦バー`|`やカンマが多い）で詰められて入っています。タグなしの項目は空です。
- **Time Added（追加日時）** — 保存した時刻。人間が読める日付ではなくUnixタイムスタンプ（`1709251200`のような、1970年からの秒数を表す長い数値）で格納されます。スプレッドシートでは巨大な整数として見え、変換するまで日付になりません。
- **Status（ステータス）** — 未読かアーカイブか。Pocketのエクスポートは通常「未読」と「アーカイブ」を分けてくれるので、アクティブなキューと、すでに格納済みのものを区別できます。

何が*入っていないか*も同じくらい大事です。Pocketがリーダー用にキャッシュしていた、クリーンに整形された記事本文はありません。ハイライトと注釈も、限定的か別扱いで、プレーンなエクスポートでは生き残らないことの方が多いです。このファイルは「保存の歴史」の忠実な記録であって、読もうとしたもののオフラインコピーではないのです。

## エクスポートファイルのフォーマット

後期Pocketのエクスポートは**CSV**（カンマ区切りテキスト）です——プレーンテキスト、1保存につき1行、列はカンマ区切り——ライブラリが大きい場合、**ZIP圧縮**され、**複数CSVに分割**されて届くことがあります。古いPocketエクスポートは代わりに単一の**HTMLブックマークファイル**（ブラウザのブックマークバックアップと同じ形式）でした。どちらもプレーンテキストでどちらも可搬性がありますが、CSVの方がスプレッドシートで読める分使いやすいだけです。

開く前に知っておきたいフォーマットの細部：

1. **ZIPラッパー。** `.zip`でダウンロードしたら、まず解凍。中におおむね1つ以上の`.csv`、たいてい未読とアーカイブの集合に分かれています。
2. **分割ファイル。** 巨大ライブラリは、個々のファイルを扱いやすいサイズに保つため分割されます——ふつう**約1万行ずつ**。`part_1`、`part_2`のような番号付きCSVが見えても、何も欠落していません。保存が分散しているだけです。インポートは1枚目だけでなく全部を行います。
3. **区切り文字入りのタグ。** 1つの項目のタグは全部1セルに詰められています。CSVの「1フィールドに多数値」の常道ですが、同時にインポートが最もつまずく場所でもあります（下記参照）。
4. **Unixタイムスタンプ。** 「追加日時」は1970年からの秒数整数で、日付ではありません。優れたインポータは自動変換しますが、スプレッドシートでは日付式を当てるまで生の整数のままです。

フォーマットが問題になるのは、次のツールへの着地品質を決めるからです。CSVはどのアプリでも読める——良いことです。ただし「どこでも読める」と「どこでも同じ解釈をされる」は別物で、そこがまさに落とし穴の発生源です。

## インポートでよくある落とし穴

一番よく事故るのは**タグの詰め方、想定外・余剰の列、本文の欠落**の3つ——ファイルの形を知っていれば全部予測できるものです。「エクスポートが壊れている」のではなく「インポータごとに同じファイルの読み方が違う」のです。以下は、特定のツールの約束事ではなく、エクスポートというファイル自体の事実として押さえてください。

- **タグが1フィールドに詰められている。** 全タグが区切り文字つきの1セルなので、その正確な文字で分割しないインポータは`productivity|focus|deep-work`を1個の巨大タグとして読むことがあります。データは無傷。個別のタグとして着地するかは、受け取る側の解析処理次第です。
- **余剰・奇怪な列。** Pocketエクスポートには一部のインポータが想定しない列が入ることがあり、列順や列名もエクスポートのバージョンで揺れています。ヘッダーに厳密に紐づくインポータは、未知の列で詰まったり、静かに無視したりします。CSVを先に開いて実ヘッダーを見れば、何が相手か分かります。
- **タイムスタンプは変換前に「間違い」に見える。** Unixタイムスタンプは巨大な数値のままか、単位（秒かミリ秒か）を誤読したツールによって間違った日付になることがあります。「追加日時」データ自体は正しい——解釈の問題です。
- **本文が無い＝死んだリンクは再構築できない。** エクスポートは中身ではなくリンクなので、読書ビューを再構築するツールはライブWebからページを再取得する必要があります。すでにオフラインになったURLには取得すべきものがない——保存はリンクとして生き残っても、読める記事は戻らないことがあります。
- **編集して保存し直してからインポート、は禁止。** スプレッドシートで開いて保存し直すと、エンコーディングが黙って変わり、タイトル内のカンマが化け、タイムスタンプが再フォーマットされることがあります。確認したければ「見るだけ」。インポートは触っていないオリジナルのファイルで行ってください。

正直なまとめ：Pocketエクスポートはきれいに構造化された優良ファイルです。ただし「リスト」であり、上の癖は全部そこから来ています。事前に知っていれば、半分しかインポートされていない状態を「インポータの故障」ではなく「タグの区切り文字の問題」として読めるようになります。

## エクスポートファイルの実際の使い方

正しい手は、**各リンクを再保存し、ライブページから読書ビューを再構築してくれる「あとで読む」系かブックマーク系ツールへ、記事がまだオンラインのうちに取り込む**ことです。エクスポートはキャッシュ済みコンテンツではなくURLを担いでいるので、回収できる価値はURLが生きているかに依存します。待てば待つほど、リンクは腐っていきます。実務手順は短いです：

1. **全ファイルを探す。** Downloadsフォルダと古いメールを掘ってエクスポートを探します。ZIPなら解凍、分割CSVなら全部集めます。Pocketのデータは2025年11月12日に完全消去済みなので、このファイルが現存する唯一のコピーです——何より先にバックアップしてください。
2. **中身をのぞく（任意）。** 無料の[Pocket Export Converter](/tools/pocket-export-converter)や[Bookmark File Viewer](/tools/bookmark-file-viewer)（[無料ツール集](/tools)内）で、CSVアーカイブの確認・検索・ブラウザHTMLへの変換ができます。
3. **移り先を決めてインポート。** [PocketからMarqlyへの移行ガイド](/migrate/pocket)、または汎用の[Migration Center](/migrate)へ。新しいツールのインポート画面にファイルを追加——分割されていれば全ファイルを——してください。ツールはリンク一覧を再保存し、各ページをライブWebから取得して読めるビューを再構築します。区切り文字タグとUnixタイムスタンプを「使えるもの」に変換するのもこのステップで、出来はツールによります。MarqlyがPocketから読み込めるのはlist.csv形式です。
4. **生存者スポットチェックと再保存。** 数件を抜き出して、ちゃんと引っ越してきたか確認します。404するリンクはライブラリだけでなくライブWebからも消えたもの——大事なやつなら、アーカイブ版を探して今のうちに再保存してください。

「どこへ着地するか」や「保存習慣の再構築」まで含めた完全手順は[Pocketデータの書き出しと移行ガイド](/ja/blog/how-to-export-migrate-pocket-data-2026)にあります。行き先をまだ比較中なら、まず[あとで読むアプリ全体](/ja/blog/ato-de-yomu-app-2026)を見渡し、Instapaperが候補に入るなら[Instapaper代替5選](/ja/blog/instapaper-alternatives-2026)もどうぞ。

## エクスポートに入っているもの vs 入っていないもの

期待値を正しく設定すれば、インポートでがっかりすることはありません。ファイルが担ぐものと、置き去りにしていくものの線を明確に引きます：

| エクスポートに入っている | 入っていない |
|---|---|
| 保存したURL（あなたのリンク） | 記事全文／Pocketがキャッシュした読書ビュー |
| ページタイトル | 頼れるハイライト・注釈 |
| タグ（1フィールドに区切り詰め） | Pocketアプリ内のフォルダ／見た目の並び |
| 追加日時（Unixタイムスタンプ） | 後にオフライン化したページのコピー |
| 読了／アーカイブの状態 | エクスポート取得*後*に保存したもの全部 |

左列は、まさに保持する価値のある部分です——「あなたが保存するほど気にかけたもの」の地図です。右列が「早めのインポート」を勧められる理由で、読めるコンテンツはファイルの*中に無い*ので、ライブWebで年々腐っていくURLから再構築するしかないのです。
